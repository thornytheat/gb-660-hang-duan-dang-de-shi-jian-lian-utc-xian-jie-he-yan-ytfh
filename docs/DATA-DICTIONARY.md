# 数据字典

- run_id：规则版本、生效基准版本与输入 SHA-256 前 12 位组成的稳定批次标识。换基准后同一输入不会复用旧运行。
- line_no：从 1 开始的物理来源行号，不因隔离或排序改变。
- business_key：本项目声明的业务唯一键，始终按字符串存储。
- reason_code：隔离原因的稳定英文编码。
- accepted：进入业务计算的记录数。
- quarantined：保留证据但不参与业务计算的记录数。
- 数值：金额、税额、用量和权重使用 Decimal；对外序列化为字符串。
- 时间：存储为带偏移的 ISO 8601，分桶使用半开区间。
- 空值：缺失键、空串和业务哨兵分别记录。
- 幂等：完整输入字节与规则版本相同则复用 run_id，不新增结果。

## 时区基准与修正发布

- baseline_version：一次结论依据的机场基准版本，例如 `TZ-2026.10`。旧结论永远保留其发放时的版本，不随新版本回写。
- baseline_digest：该版基准全量快照的 SHA-256。两个摘要相同即可确认“同一版基准”。
- baseline_effective_from：该版基准开始用于新发放的日期。修正按区间生效，历史区间保持原映射。
- fix_id：修正批次标识，由来源基准与目标基准唯一确定（如 `FIX-TZ-2026.10-TZ-2026.11`）。同一批次重复执行必复用。
- scope.affected_airports：两版基准逐区间对照后真实变化的机场，批次只登记经过这些机场的航段/转机。
- scope.baseline_changes：逐机场的旧区间与新映射，交接时可直接看出改了什么。
- scope.ignored：重复执行时本次传入、但不在首次登记范围内的航段/转机；不进入交接清单。
- 前后证据：每条受影响航段/转机都同时保存 `before` 与 `after`，各自带 baseline、当地时刻、时区、偏移、UTC、基准摘要与等待/要求分钟。
- 失败审计：`correction_failures` 只记录失败的 reason_code 与尝试时间；失败不写批次、不写交接项、不推进现行基准。
- 现行基准：所有 PUBLISHED 批次目标版本中生效日最晚的一版；没有已发布批次时退回默认版。
